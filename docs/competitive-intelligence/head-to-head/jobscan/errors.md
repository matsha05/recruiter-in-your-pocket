# Jobscan: errors checked against the unchanged input

These findings concern the with-posting report. They were checked against `input/resume.txt`, the corresponding PDF, `result-with-posting-raw.txt`, and the report screenshots.

1. **Education section missed.** Jobscan says, “We couldn't find an \"Education\" section in your resume.” The input has the heading “Education and Certifications”, followed by Oklahoma State University, “B.S. Business Administration - Marketing and Finance focus”, graduation, and SHRM certification details. This is a section-recognition failure, not missing education. The same report separately says the education matches the required bachelor's degree.
2. **Summary section invented.** Jobscan says, “We found a summary section on your resume. Good job!” The input begins with the name and redacted contact line, then “Professional Experience” and the OpenAI role. It has no summary section or introductory summary paragraph.
3. **Placeholders treated as actual contact details.** Jobscan says, “You provided your email” and “You provided your phone number.” The supplied PDF contains only “[EMAIL] / [PHONE]”; neither an email address nor a telephone number is present. This result is caused by the controlled contact redaction and does not establish how Jobscan would handle the original unredacted contact details.
4. **Unsubstantiated resume keyword count.** The “Committed” soft-skill row shows Resume = 1 and Job Description = 1. “Committed” does not appear in the unchanged resume text. It appears in the posting's company description (“committed researchers”). Jobscan did not identify a resume line supporting its count. This is a source-count discrepancy; the capture does not establish why it occurred.
5. **Quoted snippets are sometimes paraphrases.** The “Measurable Results” panel puts ellipsis-delimited excerpts in quotation marks, but some wording differs from the source. For example, `"...Achieved a 300% reduction in..."` corresponds to “achieving a 300% reduction in time to hire”; `"...Contributed to 1,000+ ML..."` corresponds to “contributing to 1,000+ ML Gen hires”; and `"...targeting $1B+ enterprise..."` corresponds to “to target $1B+ enterprise cloud deals”. These examples preserve the numerical facts but are not verbatim source quotations. This is a quotation-fidelity discrepancy, not evidence of an invented numerical achievement. The input file was not edited.

Not counted as errors: the address finding explicitly allows an incomplete address, and the input intentionally has no street address; “Technical Recruiter” and the spelled-out phrase “Machine learning” are not literal phrases in the resume. The reported word count of 826 was not labeled wrong because Jobscan's tokenization rules are not shown. Locked findings could not be checked. No visible line was attributed to the wrong employer in the reviewed report.

Without-posting attempt: not assessable because no report was generated; “Scan” remained disabled with the job description empty.
